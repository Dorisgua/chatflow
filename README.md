# Chatflow 项目总览

更新日期：2026-08-17

这个目录用于开发一个以隐私为前提的个人视觉活动助手：摄像头采集现实画面，电脑在本地理解物体和场景，最终形成“我今天大致做了什么”的可检查文字时间线。

## 一级文件夹

| 文件夹 | 一句话用途 |
|---|---|
| `nova9-local-camera` | Huawei Nova 9 手机端摄像头应用，通过带随机令牌的私有局域网地址传输实时 MJPEG 画面。 |
| `nova9-local-analyzer` | 电脑端本地 YOLO 分析器，每秒抽取约一帧并识别、标注常见物体。 |
| `nova9-local-scene` | 电脑端本地 MiniCPM-V 场景理解程序，生成场景描述、详细活动记录和可选的加密时间线。 |
| `nova9-local-calendar` | 独立的只读本地活动日历，已能把最小化活动总结呈现为电脑周视图，并为后续手机查看保留边界。 |
| `nova9-local-scene-backups` | 场景理解程序的重要可恢复版本备份，用于比较效果和安全回退。 |
| `project-positioning` | 汇总相近开源项目的横向对比、我们的优势与缺口，以及“本地推理、分析后遗忘画面”的目标定位。 |

程序第一次保存活动记录后，还会建立独立的数据目录：

| 文件夹 | 一句话用途 |
|---|---|
| `nova9-activity-records` | 按日期保存加密详细记录和最小化的明文活动总结，不与程序代码或备份混放。 |

## 模型下载与配置

本项目使用 **MiniCPM-V 4.6** 进行本地场景理解，模型文件需单独下载，不包含在本仓库中。

| 模型文件 | 用途 | 下载地址 | 放置目录 |
|---|---|---|---|
| `MiniCPM-V-4_6-Q4_K_M.gguf`（约 505 MiB） | MiniCPM-V 4.6 的 Q4_K_M 量化主模型 | [下载](https://modelscope.cn/models/OpenBMB/MiniCPM-V-4.6-gguf/resolve/master/MiniCPM-V-4_6-Q4_K_M.gguf) | `nova9-local-scene/models/` |
| `mmproj-model-f16.gguf`（约 1,057 MiB） | MiniCPM-V 配套视觉投影组件 | [下载](https://modelscope.cn/models/OpenBMB/MiniCPM-V-4.6-gguf/resolve/master/mmproj-model-f16.gguf) | `nova9-local-scene/models/` |
| `yolo26n.onnx`（约 9.5 MiB） | YOLO26n 物体检测模型 | [下载](https://github.com/ultralytics/assets/releases/download/v8.4.0/yolo26n.onnx) | `nova9-local-analyzer/models/` |

下载后，目录结构应为：

```text
chatflow/
├─ nova9-local-scene/
│  └─ models/
│     ├─ MiniCPM-V-4_6-Q4_K_M.gguf
│     └─ mmproj-model-f16.gguf
└─ nova9-local-analyzer/
   └─ models/
      └─ yolo26n.onnx
```

如果 `models` 文件夹不存在，请自行创建。请保持文件名不变；场景理解功能需要同时具备主模型和视觉投影组件。模型校验值见对应项目目录中的 `SHA256.txt`。

以上仅为模型配置，运行程序还需要 Java、llama.cpp 或 ONNX Runtime 等对应依赖。

## 产品目标

产品不是单纯“识别椅子或杯子”，而是帮助用户低负担地回顾一天，例如：

```text
09:10–09:45  电脑工作
09:45–10:05  离开画面
10:05–10:35  面对面交流（模型推测，可信度中）
10:35–11:20  阅读学习
```

核心价值是：**尽量在本地理解生活，同时让用户知道模型看到了什么、推测了什么、保存了什么。**

## 产品链路

```text
Nova 9 摄像头
→ 私有局域网传输
→ YOLO 识别可见物体
→ MiniCPM-V 理解场景和活动
→ 用户检查原始回答与整理结果
→ 本地文字时间线
→ 每日总结
→ 只读活动周日历
```

目前 YOLO 和 MiniCPM-V 是两个独立程序，便于分别验证速度、准确性和隐私；在两者价值都确认后，再考虑合并成完整产品。

## 已做功能与产品原因

| 已做功能 | 做了什么 | 为什么要做 |
|---|---|---|
| Nova 9 本地摄像头 | 手机预览并通过私有 Wi-Fi/热点传输画面，进入后台立即停止。 | 先复用已有手机验证需求，避免过早投入硬件、供电和外壳设计。 |
| 私有地址和随机令牌 | 电脑只接受私有 IPv4 地址，手机流地址包含一次性随机令牌。 | 缩小视频流暴露范围，降低局域网内被随意访问的风险。 |
| 本地 YOLO | ONNX 模型在电脑内存中识别 COCO 常见物体并画框。 | 先回答“画面里有什么”，获得速度快、容易验证的视觉基础能力。 |
| 本地 MiniCPM-V | llama.cpp 在 `127.0.0.1` 上运行量化视觉语言模型。 | 从“物体”提升到“场景和可能活动”，同时保持断网可运行。 |
| Demo 快速模式 | 只分析最新一帧、限制输出并保留第一句话，当前约5～6秒。 | 用最小等待时间验证用户是否真正需要场景描述，而不是一开始追求复杂系统。 |
| 三帧详细模式 | 分析最近三帧，区分直接观察、活动推测和不确定性。 | 利用短时间上下文减少单帧歧义，并提醒用户模型推测不等于事实。 |
| 模型原始回答页 | 同时展示 MiniCPM-V 未整理的原始 `content` 和程序整理后的显示内容。 | 降低黑盒感，让用户能检查程序有没有删改或隐藏模型回答。 |
| 详细活动记录 | 记录固定活动类别、场景、直接观察、推测依据、不确定性、可信度和耗时。 | 为全天时间线提供可检查的中间证据，而不是只给一个无法追溯的结论。 |
| 每2分钟记录 | 记录模式定期分析最新一帧，而不是保存连续视频或每秒推理。 | 全天使用不需要逐帧分析；降低 CPU 占用、重复记录和隐私暴露。 |
| 10秒断线保护 | 10秒没有新帧就清除旧预览、暂停推理并标记数据缺失，连续收到新帧后自动恢复。 | 防止网络中断时反复分析旧照片，避免生成错误的全天活动记录。 |
| 时间线推理耗时 | 每条活动记录显示本次本地模型用了多少秒。 | 让用户直接评估速度和稳定性，为以后选择CPU、GPU或硬件提供依据。 |
| 主动加密保存 | 只有用户点击保存并设置密码后，才写入 AES-256-GCM 加密的详细文字。 | 让记录权掌握在用户手中，并保护包含原始回答的敏感详细内容。 |
| 最小化明文总结 | `daily-summary.md` 只保留时间、活动类别和可信度。 | 方便用户直接阅读，同时避免把人物、环境和原始回答暴露在明文文件中。 |
| 不保存图片和视频 | 推理图片只短暂存在内存，记录文件不包含图像、手机地址或令牌。 | 用户的目标是回顾活动，不是建立高风险的生活录像库。 |
| 校验和与本地自检 | 校验模型来源、拒绝公网地址、测试真实本地推理和加密读写。 | 用可以重复执行的证据证明系统能运行，而不是仅依赖口头保证。 |
| 可恢复版本备份 | 保存三帧详细版和单帧快速版的代码、文档及编译结果。 | 新功能出现退化或引发担忧时，可以快速回到已验证版本。 |
| 独立活动周日历 | 只读 `daily-summary.md`，按真实时间比例显示一周活动格子，支持日期导航、最近记录和点击摘要。 | 把零散文字变成可以回顾时间分配的产品界面，同时不让展示功能接触图片和加密详情。 |
| 横向对比与目标定位 | 对比OpenGlass、Omi、ReflectWorld、Hindsight、ActivityWatch等项目，并记录可借鉴部分、许可证边界和当前缺口。 | 防止为了追赶功能数量而偏离隐私目标，明确产品真正要验证的问题。 |

## 产品原则

1. **先验证价值，再做硬件。** 手机原型能回答“用户是否真的需要”，独立摄像头只能改善形态，不能替代需求验证。
2. **默认少收集。** 能用文字解决就不存图，能用低频抽样解决就不连续录像。
3. **事实与推测分开。** “看到书和杯子”是观察，“正在阅读或喝茶交流”是推测，两者不能混写。
4. **用户主动控制。** 开始、暂停、保存、解密和清除都由用户明确触发。
5. **可解释优先。** 保留模型原始回答、整理规则、模型版本和耗时，避免无法检查的隐藏处理。
6. **模块逐步组合。** 采集、物体识别、场景理解、时间线先分别测试，再决定是否合并。

## 当前阶段与下一步

当前已完成从 Nova 9 到本地场景描述、加密文字记录和只读周日历的完整技术闭环，但还没有证明全天活动判断足够准确。

下一步优先级：

1. 使用独立的 `nova9-local-calendar` 检查真实周日历的可读性和活动时长估算。
2. 周日历验证有用后，增加由用户主动开启的私有局域网手机查看。
3. 再测试30～60分钟，记录活动判断正确率、编造情况、平均耗时和 CPU 状态。
4. 根据真实错误调整活动类别、提示词和记录间隔，不急于重新训练模型。
5. 时间线和日历确实有用后，再把 Nova 9 替换为 XIAO ESP32S3 Sense 等独立摄像头。
6. 硬件阶段重点解决供电、佩戴、Wi-Fi稳定性、暂停开关和明显的工作指示灯。

## 目录维护约定

- 新增一级文件夹时，在“一级文件夹”表格补充一句话用途。
- 程序代码、用户记录和版本备份保持分离，避免备份代码时复制私人活动数据。
- 每个可运行项目保留自己的 `README.md`、`PRIVACY.md`、校验值和自检入口。
- 重大功能完成前先备份已验证版本，并在本文件补充“做了什么、为什么做”。
- 任何开始保存新类型数据的功能，都必须同步更新对应项目的隐私说明。
