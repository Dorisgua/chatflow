# 横向对比与目标定位

更新日期：2026-08-17

本文档用于比较与本项目相近的开源或源码可见项目，并明确我们准备做什么、不准备做什么。比较结果是当前调研快照，项目功能、许可证和维护状态以后可能变化，正式引用或复用代码前需要再次核对。

## 一句话目标定位

**一个完全本地、分析后遗忘画面、只留下最小化活动日记的个人时间记录器。**

其他同类项目多数希望保存更多内容，以便以后搜索和回忆；本项目希望在尽可能少保存个人数据的前提下，回答“我今天大致做了什么”。

## 目标用户价值

用户不需要主动打卡，也不需要保存全天录像。系统以低频方式观察现实活动，在本地形成可检查的文字记录和日历，帮助用户回顾：

- 今天主要做了哪些活动。
- 大致在什么时间发生。
- 哪些是模型直接观察，哪些只是推测。
- 哪些时段没有数据或无法判断。
- 模型保存了什么，以及没有保存什么。

## 核心差异

1. **推理后遗忘画面。** 图片只为当前推理短暂进入内存，默认不建立生活录像库。
2. **完全本地优先。** 摄像头、模型、记录与日历组成的主要链路在断网后仍可运行。
3. **观察现实活动。** 不只统计电脑窗口或网页，还尝试理解阅读、交流、用餐、移动和休息。
4. **事实与推测分开。** 保存直接观察、活动推测、判断依据、可信度和不确定性。
5. **默认最小化保存。** 明文只保留时间、活动类别和可信度，详细内容由用户主动加密保存。
6. **低成本验证。** 先用旧手机完成产品验证，再用XIAO等小型硬件改善便携形态。

## 当前主要缺口

| 缺口 | 当前情况 | 为什么重要 |
|---|---|---|
| 连续活动理解 | 主要依靠每2分钟的一张画面推测活动 | 单帧难以区分工作、看视频、发呆等相似静态场景，也不能精确判断起止时间 |
| 真实准确率评测 | 已能运行，但没有成规模的人工真值对照 | 没有评测就无法诚实回答产品究竟有多可靠 |
| 人工纠正 | 用户目前只能查看结果，不能方便地修正活动类别 | 模型一定会误判，纠正能力是长期可用的必要条件 |
| 日/周/月总览 | 已有周日历格子，但统计和趋势仍有限 | 用户最终需要的是时间分配结论，而不是逐条模型输出 |
| 手机体验 | 手机目前主要作为摄像头 | 还缺少方便的本地手机查看、纠正与控制界面 |
| 硬件实测 | XIAO、电池、散热和外壳尚未完成真机验证 | 全天携带是否可靠取决于功耗、温度、Wi-Fi和佩戴方式 |
| 安全工程 | 已有私有地址、随机令牌和加密保存，但未经过正式审计 | 本地运行不等于绝对安全，还需要构建、依赖和网络边界检查 |
| 发布成熟度 | 当前以源码、命令脚本和独立Demo为主 | 正式产品还需要安装器、升级、崩溃恢复、日志控制和更多自动测试 |

## 借鉴边界

| 我们需要的部分 | 优先参考 | 不直接照搬的原因 |
|---|---|---|
| XIAO硬件、电池和外壳 | OpenGlass | 项目已停止单独维护，原软件也包含云端服务 |
| XIAO摄像头视频传输 | XIAO摄像头示例 | 示例缺少我们需要的访问令牌、隐私状态和断线语义 |
| 连续事件和场景记忆 | ReflectWorld | 系统过重，而且长期实体记忆不符合默认少收集原则 |
| 日历和每日统计 | Hindsight | 数据源是电脑活动，不是现实摄像头活动 |
| 活动事件结构与合并 | ActivityWatch | 需要遵守MPL-2.0，且其事件语义主要围绕电脑使用 |
| 重复过滤和事件采样 | Screenpipe的设计思想 | 当前许可证不是宽松开源，且长期保存原始屏幕和音频不符合我们的默认策略 |
| 硬件—手机—电脑产品架构 | Omi | 默认云端链路与本项目的离线隐私目标不同 |

## 当前产品策略

项目暂时不追求成为一个“记住一切”的通用个人AI，而是先验证一个更窄的问题：

> 在不保存全天图片和视频的情况下，本地视觉模型能否生成足够有用、足够可信的个人活动时间线？

近期优先级应放在连续活动判断、人工纠正和真实准确率评测，而不是快速堆叠音频、人物身份、云端记忆或复杂智能体功能。
