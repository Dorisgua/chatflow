# 隐私说明

## 本工具主动执行的网络连接

1. 手机视频：只接受 `10.x.x.x`、`172.16–31.x.x`、`192.168.x.x` 的私有 IPv4 地址，拒绝域名和公网 IP，并使用 `Proxy.NO_PROXY`。
2. 模型请求：固定发送到 `http://127.0.0.1:17861`，使用直连代理选择器。
3. llama.cpp：由程序使用明确的本地 `-m` 和 `--mmproj` 文件启动，并只绑定 `127.0.0.1`；不使用会自动下载模型的 `-hf` 参数。
4. 运行器显式启用 `--offline`、`--log-disable`、`--no-webui`，关闭外网访问、运行日志和自带网页界面；同时生成一次性的内存 API 密钥保护本机推理端点。

## 不保存的内容

- 摄像头 JPEG、解码图片和多帧序列；
- 手机地址及其32位安全令牌；
- 本地模型一次性 API 密钥；
- Base64 图片请求体；
- llama.cpp 请求和响应日志。

画面、内存缩放后的最近3帧、Base64请求和文字会短暂存在 Java/llama.cpp 的进程内存中。停止后程序会覆盖仍可直接访问的 JPEG 字节数组、释放对象引用，并等待 Java 和 Windows 回收内存。缩放与重新编码使用内存流，不生成临时图片文件。

连续10秒没有新帧时，程序会覆盖并清除最后预览及最近帧队列，暂停模型调用；中断期间不会把旧画面当成新画面继续分析。恢复需要连续两次检查观察到新帧。记录模式只添加一条不调用模型的“数据缺失”文字事件。

## 可选的文字记录

活动记录默认只在运行内存中。只有点击“加密保存今天”并设置密码后，程序才在独立目录 `D:\Documents\chatflow\nova9-activity-records` 写入：

- `activity-details.json.enc`：AES-256-GCM 认证加密的详细文字，包括模型未经整理的原始回答、整理后的显示文字、结构化活动字段和推理耗时；
- `daily-summary.md`：未加密的简要时间线，只含时间、活动类别、可信度；
- `record-info.json`：未加密的格式版本、模型名称、记录数量和“不保存图片/视频”标记。

密码通过 PBKDF2-HMAC-SHA256（210,000 次迭代、随机盐）生成 AES-256 密钥，文件使用随机 GCM Nonce。密码不写入文件；忘记密码后无法恢复详细记录。加密保护的是硬盘上的详细文件，程序解密显示时文字仍会短暂存在进程内存中。

## 必须诚实说明的边界

- Windows 可能把一部分进程内存写入系统分页文件；“应用不保存文件”不等于密码学意义上的内存立即抹除。
- `daily-summary.md` 和 `record-info.json` 是明文。前者有意限制为简要活动，仍可能透露作息；不需要时应删除或改为今后全加密设计。
- 模型原始回答可能包含错误推断，也可能意外提及画面中的敏感文字；程序提示模型不要转录屏幕、证件和账户文字，但这不是绝对保证，因此原始回答只进入加密详细文件。
- llama.cpp 和 MiniCPM-V 是第三方供应链组件；本项目保存官方来源与校验值，但不能从哲学意义上证明任何二进制绝对无害。
- 手机到电脑仍是局域网 HTTP。只能在你控制的 Wi-Fi或热点中使用。
- 模型可能对场景做出错误推断；不要把输出用于身份、健康、财务、安全或纪律决定。
- 最强的简单验证是阻止 `java.exe` 和 `llama-server.exe` 访问公网，并在断互联网状态下完整重启测试。

## 源码快速审查点

在 `src/Nova9LocalScene.java` 中搜索：

- `validateAndBuildStreamUri`：手机地址白名单；
- `Proxy.NO_PROXY`：手机局域网直连；
- `127.0.0.1`：唯一模型服务地址；
- `ProcessBuilder`：llama.cpp 只使用本地模型文件；
- `Base64`：内存图片发送给本机模型服务；
- `ActivityRecord`：明确保存的文字字段，不含图像字节；
- `EncryptedRecordStore`：唯一的持久化实现、固定记录根目录和加密格式；
- 源码中没有图片写盘、云 API 密钥或遥测 SDK。
