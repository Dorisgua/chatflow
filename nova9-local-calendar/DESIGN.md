# 活动日历设计

## 产品定位

这是“活动回顾日历”，用于回答过去一段时间大致做了什么，不用于规划未来事项，也不自动写入华为、Google 或 Apple 系统日历。

## 电脑界面

第一版已经按以下方案实现。

默认使用周视图：

```text
‹ 上一周       2026-08-17—2026-08-23       今天       下一周 ›

时间      周一          周二          周三          周四……
09:00
10:00    ┌────────┐
         │💻电脑工作│
         │约28分钟 │
11:00    └────────┘
```

活动格子同时使用文字、图标和颜色，不能只依靠颜色表达类别。数据缺失使用灰色斜纹；空白表示当时没有记录，不能自动解释为休息。

## 手机界面

手机使用“月历 + 所选日期的纵向时间线”，避免把七列周视图压缩到窄屏：

```text
2026年8月
一 二 三 四 五 六 日
             17●

8月17日
10:41—11:09  💻 电脑工作  约28分钟
11:10—11:30  📖 阅读学习  约20分钟
11:30—11:40  数据缺失
```

## 第一版数据规则

1. 第一版读取已经保存的 `daily-summary.md`，不读取加密详细记录。
2. 连续相同活动合并成一个格子。
3. 时间段来源于总结文件，因此统一使用“约”表示估计时长。
4. `数据缺失`、`离开画面`、`无法判断`和无记录必须分别显示。
5. 可信度按已有总结显示，不在日历中重新推断。
6. 日历是只读视图，不自动修改模型结论。

## 手机查看阶段

这一部分尚未实现，属于第二阶段。

第一阶段是临时查看，不复制永久数据：

1. 用户在电脑端主动点击“在手机上查看”。
2. 服务只绑定私有局域网地址，并生成新的随机会话凭据。
3. 手机只获得日期、时间段、类别、可信度和记录状态。
4. 用户停止共享或关闭程序后，会话失效。
5. 响应禁止缓存，不提供图片、视频、原始模型回答或摄像头凭据。

真正的手机离线保存属于后续阶段，需要独立评估手机加密存储、删除语义和设备丢失风险。

```text
├─ README.md
├─ DESIGN.md
└─ PRIVACY.md
```

手机页面实现时才会新增 `web/`；当前版本没有开启任何网络服务。
